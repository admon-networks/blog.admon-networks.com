先に結論を書きます。

1.  **CBTでは、問題を解き始める前に「問題文の表示」を調整しておく。** 問題文は別枠で表示できますが、最初の状態では表示が大きすぎて使いにくかったです。表示の大きさや文字サイズは調整できるので、最初に自分の見やすい状態にしておくのがおすすめです。
2.  **学習の配分は、A群まではA対策が8割、A群のあとはB群に集中。** 本格的に始めたのは10月で、平日は通勤中心に1〜1.5時間、休日は2時間でした。

以下、受験の概要、CBTで気をつけること、学習の配分と教材、演習の推移、B対策のやり方の順に書いていきます。

## CBTで一番気をつけてほしいこと

### 問題文の表示は、最初に調整しておく

これが、この記事で一番伝えたいことです。

CBTでは、問題文を別枠（別の表示領域）で表示できます。ただ、最初の状態だと表示が大きすぎて、正直使いにくかったです。

表示の大きさや文字サイズは調整できます。なので、これから受ける人は、**問題を読み始める前に、別枠の表示の大きさと文字サイズを自分の見やすい状態に合わせておく**ことをおすすめします。

ネスペは、とにかく問題文を読む量が多い試験です。特に科目Bは長文で、本文と図や表を行き来しながら読むことになります。見づらい状態のまま読み進めると、そのぶん集中力も時間も削られます。

> [!TIP] 試験が始まったら最初にやること
> 問題文の別枠表示の大きさと、文字サイズを調整する。解き始めてから直すより、最初に済ませておくほうが落ち着いて読めます。

## 科目B群の対策

### 教材の役割分担

- **ネスペR7**：B対策の中心。演習はこれをベースに進めました
- **IPAの過去問と採点講評**：過去問の演習と、採点講評の確認に使用
- **うかるネットワークスペシャリスト**：通して読むのではなく、分からない技術や用語を引く辞書として使用

### 平日は「帰りに解いて、翌朝に復習」

Bの演習は、次のリズムで回していました。

- **平日**：帰りの電車で新しい問題を1問解く → 翌朝の電車で復習する
- **土日**：B-2を1問解く
- **順番**：直近の年度からさかのぼって解く

学習の中心が通勤時間だったので、Bも電車の中で回せる形にしました。解く時間と復習する時間を分けて、帰りと翌朝に割り振っています。B-2は1問あたりの分量が多いので、まとまった時間が取れる土日に回しました。

### 誤答ログで、間違えた原因を分類する

間違えた問題は誤答ログに記録して、原因を分類していました。分類は主に次のようなものです。

| 分類               | 中身                                                   |
| ------------------ | ------------------------------------------------------ |
| 暗記漏れ           | 用語や仕様など、覚えていれば答えられたもの             |
| 挙動の誤解         | プロトコルや機器の動きを間違って理解していたもの       |
| 読み落とし         | 問題文の条件や、図・表の情報を見落としていたもの       |
| 問われ方の読み違い | 設問が何を答えさせたいのかを取り違えたもの             |
| 記述の核の欠落     | 方向性は合っているが、解答に必要な要素が抜けていたもの |
| 字数オーバー       | 指定の字数に収まらなかったもの                         |

原因を分けておくと、同じ「間違えた」でも打つ手が変わります。暗記漏れなら覚えればいいし、挙動の誤解なら仕組みから理解し直す必要があります。読み落としや問われ方の読み違いは、知識ではなく読み方の問題です。記述の核の欠落と字数オーバーは、記述式ならではの失点です。

「また間違えた」で終わらせずに、何が原因だったのかを一言で残しておく。これだけでも、復習のときに見るべきところがはっきりします。

## 苦手だった分野

本業がネットワークでも、次の分野は苦手でした。

- DNS
- HTTP
- データベース（SQL）
- SDN／仮想化
- A-1の範囲の広さ

なかでもデータベース、特にSQLは、最初は全くわかりませんでした。

HTTPは、圧倒的に苦手という印象がありました。過去問の演習でも、HTTPがテーマの問題は避けて選んでいたくらいです（本番ではなく、演習での話です）。

DNSの基本は、このブログの[DNSの記事](/dns/)でもまとめています。勉強中に引っかかったことを記事にしたものとしては、[IPはなぜ再送しない？TCPとの役割分担](/ip-no-retransmission-tcp/)もあります。
